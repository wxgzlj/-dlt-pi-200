# Power Analysis Specification — DLT-PI-200

**Status: PROPOSED TECHNICAL SPECIFICATION — NOT YET FROZEN; NO POWER RESULT CLAIMED**

## 1. Confirmatory design held fixed

- 200 consecutive eligible draws; five portfolios A/B1/B2/C/D; 10 distinct tickets per model per draw.
- Primary endpoint: within-draw mean front hits per ticket; inferential unit is the draw.
- Four two-sided model-vs-D comparisons; family-wise alpha 0.05; Holm step-down correction.
- MDE: +0.10 front hits per ticket versus D; target power 80%.
- At least 100,000 Monte Carlo experiments. Do not extend the horizon or change the MDE if power is low.

## 2. Unit of simulation

One simulated experiment is a 200-draw panel. For draw t and model m, calculate

`Y[m,t] = (1/10) * sum(front_hits(ticket[m,t,j], official_draw[t]), j=1..10)`.

For each candidate m in {A,B1,B2,C}, calculate the paired draw-level difference

`D[m,t] = Y[m,t] - Y[D,t]`.

Never treat the 10 tickets within a draw as 10 independent observations. The four model comparisons are correlated because they share the same official draw and D portfolio.

## 3. Null generator

Under H0, every official outcome is sampled uniformly from the 21,425,712 legal 5/35 × 2/12 combinations, independently across draws. All five ticket portfolios are generated by the frozen production generator using draw-specific inputs and seeds. If real π/history inputs are not yet frozen, the simulation must use clearly labeled synthetic fixtures and cannot be represented as final design power.

## 4. Alternative generator — proposed, not approved

Power must be evaluated separately for each focal candidate m. For a legal front outcome y, define S_m(y) as that candidate's within-draw mean front hits. Define an exponential-tilt alternative

`P_lambda(y) ∝ exp(lambda * S_m(y))`

over the finite set of legal front outcomes; the back-zone outcome remains uniform and independent. For each focal model, numerically calibrate lambda so that

`E_lambda[S_m(Y) - S_D(Y)] = +0.10`

under the actual paired ticket portfolios. The same official outcome is scored against all five portfolios, preserving within-draw dependence and cross-comparison correlation. This is a power-planning stress scenario, not a claim that a real lottery bias would take this form.

Calibration must be checked with an independent Monte Carlo sample. Report achieved effect, Monte Carlo standard error, lambda, acceptance/importance-sampling diagnostics, and whether the target was attainable. If the target cannot be calibrated reliably, do not report a power estimate for that scenario.

## 5. Test and interval procedure — proposed, not approved

- Primary test statistic: paired t statistic on the 200 draw-level differences for each candidate vs D.
- Two-sided raw p-values; apply Holm across the four primary comparisons in every simulated experiment and in the final analysis.
- Effect estimate: mean paired difference in front hits per ticket.
- 95% confidence interval: paired t interval; additionally report a draw-cluster bootstrap interval as a robustness analysis, with bootstrap resampling whole draws only.
- Power for focal model m: proportion of simulated experiments in which its Holm-adjusted primary comparison rejects at family-wise alpha 0.05.
- Also report family-wise probability of at least one false rejection under the global null, and power under each of the four single-focal alternatives.

These choices must be validated under the exact null generator before freezing. If the paired t test is materially miscalibrated, replace it only before any confirmatory draw and record a new preregistration version.

## 6. Monte Carlo governance

- Minimum 100,000 simulated experiments per null/alternative scenario.
- Publish a fixed simulation seed, PRNG specification, code hash, Python version, simulation count, and calibration seed.
- Report Monte Carlo standard error `sqrt(p_hat * (1-p_hat) / N)` for each estimated rejection probability.
- Use disjoint random substreams for calibration, null validation, and power estimation.
- Do not tune lambda, test statistics, or portfolio generation using the final power-estimation stream.

## 7. Required outputs

1. Null family-wise error rate and Monte Carlo SE.
2. Power for A, B1, B2, and C separately at the +0.10 MDE after Holm correction.
3. Power curves at 0.05, 0.10, 0.15 and 0.20 front hits per ticket, clearly labeled as planning scenarios.
4. Alternative calibration diagnostics and portfolio-dependence summaries.
5. Sensitivity to paired t vs draw-cluster bootstrap inference.
6. An explicit `ADEQUATE_FOR_MDE` or `UNDERPOWERED_FOR_MDE` status. No horizon or MDE changes are allowed after this report.

## 8. Activation gate

No power value may be reported until the alternative calibration, null type-I error check, Holm implementation, reproducibility test, and 100,000-run Monte Carlo audit pass. This specification itself does not establish 80% power.
